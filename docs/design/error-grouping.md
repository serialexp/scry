## Why this exists

Raw exception messages and minified stack strings do not identify bugs reliably.
Dynamic IDs explode message grouping, line numbers move across releases, and a
production browser stack is unreadable without the exact source map. Conversely,
changing a grouping algorithm silently can move history and trigger false “new”
issues.

This design makes stack enrichment repeatable and issue identity explainable. Raw
telemetry remains authoritative; artifacts and derived records are immutable and
versioned. No symbolication failure blocks ingestion.

## Goals

- Link generated JavaScript to exact source maps by application and debug ID.
- Retain raw, parsed, and symbolicated data independently.
- Compute stable cryptographic fingerprints from bounded canonical components.
- Explain every included/excluded grouping component.
- Support safe application overrides and deterministic fallbacks.
- Reprocess after late artifacts or algorithm changes without silent history loss.
- Bound hostile stack/source-map CPU, memory, decompression, nesting, and cardinality.

## Non-goals (v1)

- Native minidumps, DWARF/PDB/dSYM symbolication, source fetching from arbitrary
  frame URLs, or source-control checkout.
- Matching an artifact by “latest file with this URL.”
- Locals, heap state, screenshots, or code ownership inference.
- Cloning Sentry's grouping implementation byte-for-byte.
- Automatic historical regrouping on every deployment.

## Artifact and debug identity

Adopt canonical lowercase UUID text for a 128-bit debug ID, one per generated JS
artifact, embedded in generated code (`//# debugId=...`) and the source map's
`debugId`. Accept legacy `debug_id` only at upload and canonicalize it. Prefer a
deterministic ID derived from canonical generated-plus-map content while excluding
the injected ID fields. Hashing generated bytes alone is insufficient because
identical minified output can arise from different source content.

A build ID groups debug IDs for display/deployment. `service.version`, release,
dist, and generated URL are weak metadata/legacy lookup aids, never stronger than
an exact frame debug ID. Mixed builds and micro-frontends are valid. Each event's
debug metadata maps normalized code-file/module identity to a debug ID.

## Immutable artifact layout

Illustrative layout, subject to the umbrella namespace decision:

```text
_scry/artifacts/v1/apps/<app-id>/debug/<shard>/<debug-id>/
  generated
  source-map
  manifest.json             # commit object, PUT last
_scry/artifacts/v1/apps/<app-id>/builds/<build-id>/<manifest-id>.json
```

The manifest includes schema version, app/debug ID, platform/media types, byte
lengths and cryptographic digests, upload time, generated URL aliases, optional
build/release/dist, source-content policy, and tool versions. Upload payloads are
written first; `manifest.json` makes them visible through `PutMode::Create` /
`If-None-Match: *`. An identical retry verifies the existing digest and succeeds;
a different digest receives a precondition conflict and is quarantined, never
overwritten. ETag `If-Match` protects any explicitly revisioned mutable index, though
the primary artifact objects remain immutable. Deletion removes commit metadata
last. The artifact role refuses startup if its object-store capability probe cannot
prove these semantics.

Artifact upload requires a scoped high-entropy CI/operator credential (artifact-
upload capability), never a public browser key or reusable web session cookie.
Errorsd binds its control listener to loopback/private configuration and authenticates
the webui/CLI service hop with scoped bearer credentials or mTLS from the first
artifact phase. Clients supply typed app/build/debug identities, never object keys
or source URLs.
A local SQLite index is rebuilt by listing committed manifests and indexes exact
`(app_id, debug_id)` plus explicitly supported legacy `(app_id, build_id,
normalized_url)`. Cache entries include manifest ETag/digest and processor version,
are byte-bounded and single-flight, and negative entries expire or invalidate on
artifact-created hints. Valkey hints may accelerate visibility but are not truth.

`source-map` may be indexed-map JSON. `sourcesContent` is optional and sensitive;
upload policy may strip it. Serving source context is a separate authorization
capability from seeing issue metadata. Artifact contents/digests are never placed
in normal logs or status.

## Stack layers and frame model

For every occurrence retain:

1. raw exception chain, messages, natural stack string, debug metadata, and context;
2. parsed exceptions/frames plus `parser_version` and declared platform/runtime;
3. symbolicated frames plus `symbolicator_version`, exact artifact digests, per-
   frame result, and source-context policy;
4. normalized grouping components plus fingerprint/policy versions.

Do not overwrite raw function/file/line/column. Internal frames use one documented
order, positive 1-based lines/columns, normalized Unicode and slash semantics, and
both raw/display and normalized URLs. Query/fragment/host can remain for display
under privacy policy but do not normally group.

Preferred SDK input can include structured exception chains/frames; bounded natural
runtime stacks remain required for ecosystem interoperability. Parsers are explicit
`(platform, runtime, parser_version)` adapters. A declared parser failure does not
fall through to guessing another language. Aggregate/chained errors preserve causal
ordering and truncation/dropped counts.

## Symbolication

Lookup each frame in this order:

1. exact `(app_id, debug_id)`;
2. optional exact legacy `(app_id, build_id, normalized generated URL)`;
3. unsymbolicated frame.

Never choose a newer map merely because its URL matches. Validate embedded IDs,
manifest digests, media types, generated location bounds, source-map structure,
and source indexes. Per-frame status is one of `symbolicated`, `missing_debug_id`,
`artifact_missing`, `id_mismatch`, `invalid_map`, `location_unmapped`,
`unsupported`, or `resource_limit`. Partial stacks remain useful.

Remote URL scraping is off in v1. If ever added it requires a separate design for
HTTPS-only SSRF defenses, redirect/DNS/IP revalidation, private/metadata address
rejection, no ambient credentials, byte/time/decompression bounds, and immutable
capture before use.

## Fingerprint v1

A validated explicit `scry.error.fingerprint` wins. It is a bounded list of tokens,
not arbitrary executable templating. A future `{{ default }}` token may splice the
automatic components. Values are namespaced by `app_id`, length/count bounded,
canonicalized, and hashed rather than used directly as object keys.

Automatic `fp-v1`:

1. select the causal/root exception according to one documented chain order;
2. include normalized exception type;
3. select a bounded sequence of contributing in-application frames from the best
   available symbolicated stack;
4. per frame use normalized module/source path and stable function/scope, normally
   excluding line/column and volatile URL components;
5. exclude versioned framework/runtime/native/eval/anonymous low-quality frames
   and collapse adjacent recursive repetitions;
6. if no useful in-app frame remains, use a system-frame variant;
7. if no useful stack remains, parameterize exception type/message by replacing
   UUIDs, addresses, timestamps, long numbers/hashes, and URLs with typed tokens;
8. last resort is an app-scoped unknown-error bucket with explicit low quality and
   flood/cardinality telemetry.

Environment and release are facets, not default fingerprint components, allowing
one issue to express release regressions. Service/application identity scopes the
fingerprint. Canonical bytes are length-prefixed typed components containing
fingerprint version, platform, component kind/value, and grouping-policy revision.
Hash with a cryptographic 128/256-bit digest, not the xxh3 series fingerprint.

Persist the digest, all canonical components, quality, and an explanation such as
“frame excluded: system library.” A digest collision is resolved by comparing
canonical bytes and assigning a disambiguated issue identity; fingerprints are not
assumed collision-proof database primary keys.

## Issue identity and migration

Issue ID is deterministically derived from deployment/app identity, fingerprint
version, grouping-policy revision, and canonical component bytes using a wide
cryptographic digest. Equal primary digest with unequal bytes uses a deterministic
secondary full digest/disambiguator and is surfaced as a collision. It is not a
random ID requiring a linearizable allocator. Algorithm versions coexist.
Deploying code never silently recomputes historical membership.

A migration runs dual computation in shadow, reports split/merge/cardinality
changes, and then requires explicit activation/backfill scope. Derived grouping
records are keyed by event ID plus parser/symbolicator/artifact/fingerprint/rules
versions so replay is idempotent and rollback remains possible.

Late artifacts create a second grouping result. Two policies remain for review:

- keep initial issue membership stable and offer an explained merge/reprocess action;
- move occurrences atomically into the improved issue while retaining aliases,
  count deltas, redirects, and audit history.

In neither policy may events or counts silently disappear, nor may the same
occurrence count in both active issues.

## Bounds and admission

Starting qualification limits: event 1 MiB; stack 256 KiB; 32 exceptions; 256
frames each; 64 debug images; ordinary strings 8–16 KiB; source context 4 KiB;
artifact object 32 MiB compressed and separately bounded expanded (candidate 128
MiB); map 100k sources/names with token/nesting limits; build manifest 10k artifacts
and 4 MiB. These are hypotheses requiring measured qualification.

Parsing/symbolication use dedicated weighted memory admission, CPU/wall deadlines,
bounded concurrency/waiters, cancellation, and spill only if explicitly designed.
On overload retain the raw occurrence and mark processing deferred. One malformed
map or hot debug ID cannot monopolize workers. Reprocessing is rate-limited,
checkpointed, resumable, scoped, and lower priority than current occurrences.

## Retention and garbage collection

Artifacts default to at least maximum raw-error retention or remain pinned while
reprocessable occurrences reference their digest. A shorter configurable time-to-
idle makes later symbolication best-effort and must be visible. Already derived
frames may remain for display but are no longer independently rebuildable after
artifact deletion.

GC derives reachability only from a stable full listing/checkpoint plus committed
build manifests and occurrence/reprocessing references. It requires a minimum age
and two complete unreferenced confirmations; a stale local index is never deletion
authority. It tolerates interrupted deletion and removes manifests last. Orphaned
uncommitted payloads require a bounded age-based collector. Privacy deletion must
cover `sourcesContent` and derived source context.

## Failure semantics and observability

Missing/invalid/over-limit artifacts produce status and deferred/unsymbolicated
results, never raw-ingest rejection. Index rebuild failures retain the previous
published view and expose age. Late upload invalidates matching negatives and
queues bounded work. Status reports artifact/index bytes and lag, cache hit/miss/
negative/single-flight, processor queue/age/memory/timeouts, symbolication outcomes,
fingerprint quality/cardinality/collisions, and migration deltas—never source text.

## Verification

- Golden V8/source-map fixtures plus chained/AggregateError, Unicode, Windows paths,
  indexed maps, mixed builds, partial maps, and legacy lookup.
- Malformed/decompression/nesting/token/huge-source adversarial fixtures prove
  bounds before allocation and deadline cancellation.
- Fingerprint canonical-byte snapshots and order-independence/property tests.
- SeaweedFS/AWS contract tests for conditional create and ETag update; upload retry/
  collision, metadata-last visibility, interrupted GC, index rebuild,
  cache invalidation, and late-artifact reprocessing tests.
- Migration tests prove no double counts, silent movement, lost redirects, or
  false notification transitions.
